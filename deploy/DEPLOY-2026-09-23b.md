ssh deploy@46.101.176.117

### 1. Dohvat

```bash

```

Nema novih ovisnosti — `npm install` nije potreban.

### 2. Control prvi

Okolina SEOP-a se cita iz `integrations_configs.test_do.json`, a ostali servisi
je uzimaju od controla PRI POKRETANJU. Restart obrnutim redom znaci da bi akd
jos minutu radio po staroj konfiguraciji.

```bash
pm2 restart travelo-control-service
sleep 3
```

### 3. Migracija — naziv na karti

```bash

```

Ocekivano: `· kolona ticket_label`.

### 4. Restart ostalih

```bash

```

### 5. Popuna kapaciteta

```bash

```

Ispis je po linijama, stupac „bez kapaciteta". Ako ijedna linija nije na nuli:

```bash

```

Init je idempotentan — polazak koji vec ima zapise se preskace.

### 7. Provjera

```bash

```

## Rucni unos nakon deploya

**Nazivi na karti** se upisuju u portalu: Integracije → AKD → SEOP → Popusti,
stupac „Naziv na karti". Sifra prava blagajniku ne znaci nista, a puni opis iz
Pravilnika je predug za redak kosarice — zato kratak naziv. Prazno polje znaci
da ostaje kako je bilo.

## O tunelu (preduvjet za SEOP)

Tunel drzi uredsko racunalo: `ssh -N -R 127.0.0.1:9444:seop.akd.hr:9444
seoptunel@46.101.176.117`. Na VM-u `/etc/hosts` ima `127.0.0.1 seop.akd.hr`, pa
konfiguracija u portalu ostaje nepromijenjena.

Provjera je li tunel gore:

```bash
ss -ltnp | grep 9444
```

Ako ga nema, SEOP provjere padaju s odbijenom vezom — to je ispravno ponasanje,
uredaji tada odlucuju lokalno. Vracanje na stanje bez tunela: okolinu u
`integrations_configs.test_do.json` vratiti na `mock` i restartati control pa akd.
